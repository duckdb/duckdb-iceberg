# Java-encrypted Iceberg v3 tables

Generated by [EncryptedTable.java](../../../scripts/persistent/EncryptedTable.java)
with Apache Iceberg 1.11.0 and Java 21.

- `t_enc` contains `(1, 'secret-a')` and `(2, 'secret-b')`. Its Parquet file uses
  native Parquet encryption (`PARE`); its manifest and manifest list use Iceberg
  AES-GCM encryption (`AGS1`). The snapshot records a `key-id`, and table metadata
  contains the corresponding `encryption-keys`.
- `t_enc_empty` has the same schema and `encryption.key-id = keyA`, with no
  snapshots or data files.

The generator uses Iceberg's `StandardEncryptionManager`, a fixed fixture-only
AES wrapping key, and random file keys and nonces. A small `TableOperations`
adapter adds encryption support to `HadoopTables` and persists the manager's
registered keys. All metadata, manifests, and Parquet files are written by the
Java Iceberg library. The generator reloads the persisted table with a fresh
manager, decrypts and checks both rows, and verifies the encrypted file magic.
No catalog service or external KMS is needed.

Run from the repository root with Java 21, PySpark's dependency jars, and
`iceberg-spark-runtime-4.1_2.13-1.11.0.jar` in `scripts/data_generators/`:

```sh
ENCRYPTION_FIXTURE_SPARK_JARS="$(python3 -c 'import pathlib, pyspark; print(pathlib.Path(pyspark.__file__).parent / "jars")')"
java --class-path "scripts/data_generators/iceberg-spark-runtime-4.1_2.13-1.11.0.jar:$ENCRYPTION_FIXTURE_SPARK_JARS/*" \
    scripts/persistent/EncryptedTable.java
```

The generator refuses to overwrite either table directory. To regenerate in
place, first remove only `t_enc` and `t_enc_empty`, preserving this README.
Alternatively, pass a new output root as the final argument to inspect an
adapted fixture separately. Stored paths are relative to the repository root;
changing the output root changes those paths. UUIDs, timestamps, keys, and
ciphertext change between runs.
