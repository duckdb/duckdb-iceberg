uncommitted diagnostics; DuckDB core
`a7e6fc10d2f12ba0784f0843ee9ec517dcba561b`, runtime `v2.0.0-dev89503`.
Apple M5 Pro, 18 logical CPUs, 48 GiB RAM, macOS ARM64. The `reldebug`
configuration used optimized `-O3` compilation without coverage or sanitizer

The wide delete case opened 240 data files and performed 19,200 candidate visits
and predicate evaluations: 240 × 80 live delete entries. Narrow IN and padded IN
each opened 24 files, scanned 2,392 rows, and performed 1,920 visits/evaluations.
Narrow BETWEEN scanned 2,257 rows from the same 24 files; all three independently
verified final counts were 42. Thus padding preserves the measured scan shape,
while BETWEEN changes rows produced by the scan.

Each 25,000-entry manifest query initialized one manifest reader and converted
all 25,000 entries before opening one data file. Each 35,000-snapshot staleness
query performed one table metadata conversion covering all 35,000 snapshots,
despite making no LoadTable request. ETag mode verified one HTTP 304 per diagnostic
query and retained these conversion costs.

The snapshot records have compact operation summaries and unchanged manifest
lists. The delete writer packs each statement's vectors into one Puffin file
and manifest merging is disabled. These differences, together with build/runtime
differences, mean the historical issue timings are not direct before/after
comparisons with this baseline.
